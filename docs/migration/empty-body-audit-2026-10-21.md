# 本文0 bytesの操作の点検

2026-10-21、通知の全件既読でHTTP受信時の空ReadableStreamを本文ありと誤判定した不具合
（PR #42）を受け、Workerの本文判定とフロントエンドの更新系HTTP呼出しを横断確認した。
`Request.body` がnullかどうかだけで空本文を判定しない。

| 操作 | 確認結果・回帰検証 |
| --- | --- |
| 通知の全件既読 | PR #42で実際のbytesを確認する方式へ修正済み。null・空文字列・空Uint8Arrayで本人の対象通知だけ更新し、対象外行を保持する。本文があれば更新しない。 |
| Stripe決済管理画面 | 既存実装でEOFまで空本文を受理する。隔離D1とStripe stubで空ストリームを受理し、空chunkの後にbytesが来る場合も認証・Stripe呼出し前に拒否する既存検証を実行する。 |
| 管理者の期限処理実行 | 既存実装で空ストリームを受理する。実処理を代行関数に置き換えた既存検証で、0 bytesなら1回実行し、本文ありは実行しないことを確認する。 |
| 招待コード削除 | DELETEはJSONを読まない。null・空文字列・空Uint8ArrayでMFA拒否・使用中の削除拒否・削除可能なコードの削除を隔離D1で確認する検証を追加した。 |
| 画像削除 | DELETEは画像uploadの本文判定を通らない。null・空文字列・空Uint8Arrayで他人の削除を拒否して画像を保持し、所有者だけ削除できることを隔離Auth D1/R2で確認する検証を追加した。 |
| ログアウト | clientはJSON `{}` を明示送信する。既存の実Worker/Auth D1検証で、clientからのログアウトがcookieとD1 sessionを無効化することを確認する。 |

お気に入り削除など、操作対象のJSONを必要とする経路は空本文を許可する対象ではない。
アップロードも実画像が必要で、空本文の拒否は意図した動作となる。
残りの本文存在チェックは、このようにJSON・画像・移送データを必要とする読取りの入口だった。
本点検では通知以外に同じ誤判定の不具合は見つからず、追加の実行コード変更は行っていない。
本番で決済作成・期限処理・招待や画像の削除を試すことはせず、隔離環境で副作用まで確認する。

ローカル検証は通知56件、招待7件、画像7件、決済管理7件、期限処理5件、
実Authのclientログアウト1件の計83件とWorker型検査が成功した。
ログアウトは該当1件を選択実行しており、Auth全体の実行結果とは区別する。
