## 再開する方法

イシューに記録したコミットから別の作業ディレクトリを作ると、移行中のチェックアウトを変更せずに試せる。

```sh
git fetch origin
# <保存コミット> は #26 に記録したSHAへ置き換える
git worktree add --detach ../fanmark-palette-snapshot <保存コミット>
cd ../fanmark-palette-snapshot
npm ci
TYPESAFE_API_KEY_FILE=/path/to/private-key-file npm run dev:palette
# http://127.0.0.1:4178/ （同じポートで既に起動していればそちらを利用）
```

秘密ファイルは保存対象に含めない。キーなしでも名称検索と操作は試せるが、Jevの提案にはサーバー側のキーが必要。`npm run build:palette` は静的UIだけを生成し、Jev APIを含まない。テスト・型検査・出典・試行結果は [README](./README.md) を参照。

## 保持した内容

- 入力済みの並びを外側とパレット内で共有。最大5個、指定位置への連続追加、置き換え、途中挿入、削除、並べ替え、Undo、すべてクリアと復元。検索語を保ったまま続けて選べる。
- 端末内の選択履歴は最大24件・表示8件。検索語は保存しない。削除やUndo後も選択履歴は残す試作仕様。
- 既存カタログ3,944件のIDを保持。英語の既存名称と日本語CLDRの名称検索、肌色違いの展開、全件一覧への導線。
- Jevは「分類→絵文字」の2段階。主題・場所・気持ち・関連道具・身体的反応・比喩と象徴を別々に探索する。地名の雰囲気も場所の観点で提案する。検索語ごとの手書き連想辞書は使用せず、名称検索でJevの候補を制限しない。
- 各葉の質問は最大250絵文字＋該当なし。場所・象徴は最大6群、ほかは最大2群を探索し、1検索で最大8回の外部HTTP呼び出し。異なる質問の確率を共通順位として比較せず、観点ごとに候補を交互に並べる。
- IME変換中の送信抑止、350ms待機、古い応答の破棄、キャンセル、タイムアウト、名称検索へのフォールバック。キーはサーバーのみで扱う。

## ファイルと移植範囲

| ファイル | 役割・導入時の扱い |
| --- | --- |
| `App.tsx` / `styles.css` | 操作UI。既存 `src/components/EmojiInput.tsx` の状態・コールバックへ合わせて切り出す。デモの初期値やページ全体は移植しない |
| `search.ts` / `ja-annotations.json` | カタログと名称検索。移行後の版付きマスター生成・配信に接続する |
| `useJevSearch.ts` | 非同期検索の状態制御。製品版APIの契約・エラー表示へ合わせる |
| `jev-server.ts` | 分類生成・プロンプト・候補統合とローカルVite middleware。推論部分を分離し、NodeのHTTP/ファイル読込をWorkerのRequest/Response/Secretsへ置換する |
| `jev-server.test.ts` | APIを模擬した8件の構造・回帰テスト。実モデルの検索品質評価とは別物 |
| `vite.config.ts` / `main.tsx` / `index.html` | 独立デモ用。製品版ルートにそのまま追加しない |

通常の本番ビルド・本番入力欄・Supabase・認証・Stripe・取得処理には未接続。ブラウザーの履歴、秘密情報、生成されたdistはGit保存に含めない。

## 導入前に残る確認

少数の実API試行では「東京の美味しいラーメン」の 🍜 🗼 😋 🤤、「東京の床屋」の ✂️、「AIを使ったコンサル」の 🤖、京都・原宿の連想候補を確認した。候補は確率的で再現保証はない。地名試行は約1.4〜1.5秒（350msの待機を除く）で、p95・費用・多言語の網羅的評価は未実施。未知地名にも都市や地図の汎用候補が出る問題が残る。場所の0.05、それ以外の0.01という表示閾値は試作上の調整であり、関連性の校正値ではない。

初期JSはgzip約310KB。実機のソフトウェアキーボード、アクセシビリティ、性能、全対応言語、カタログ更新互換性は製品版で検証する。現行のローカル同時実行・毎分制限やメモリーキャッシュを、そのまま公開Workerの利用制限として採用しない。

## #28 完了後の導入手順

1. 移行後の最新コードと #28 の完了条件を確認する。Apple/Google/GitHub/Discord、`auth.fanmark.id`、Stripe、データと絵文字更新の検証を含め、移行の残作業とパレット導入を混ぜない。
2. 新しい `codex/` ブランチで保存コミットの実装を参照して移植する。古いブランチ全体や旧ドキュメントを一括マージして、移行後の構成を戻さない。
3. 既存 `emoji_master.id` と正規化を保持し、`catalogVersion / normalizationVersion / dictionaryVersion / schemaVersion` をAPI・名称データ・検索グループ・履歴で整合させる。固定CLDRは版付きマスターの更新経路へ組み込む。多言語追加に全絵文字の手書き連想辞書を前提としない。
4. Jev推論をWorkerへ移植し、未ログイン利用、Secrets、本文上限、タイムアウト、利用制限、キャッシュキーと版、監視・費用上限を定める。検索語の外部送信表示を維持し、ログ保存・学習利用は別途設計する。履歴や選択済み絵文字は送らない。
5. 本番 `EmojiInput` へ機能フラグ等で段階導入する。既存5個制限・表示表記・UUID変換を守り、空き状況確認・登録・課金は既存の移行後APIへ接続する。
6. 上記の日本語・英語の例に加え、未知語、混在言語、途中入力、弱い連想、肌色・国旗の評価セットを作る。候補への到達率、上位の妥当性、初回表示/Jev反映の中央値とp95、トークン量・費用を別々に測る。
7. stagingで連続追加・置換・削除・Undo・クリア・履歴・IME・古い応答・障害時の名称検索・実機表示を検証する。マスター更新と旧履歴の互換性も確認してから本番へ反映する。

保存時点では #26 の本番受け入れチェックを完了扱いにしない。導入再開はCloudflare全面移行の完了後に行う。
