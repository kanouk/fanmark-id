# Web版絵文字入力パレットの操作サンプル

Issue #26 の「＋」から開く入力パレットを試すための独立ページ。本番の `EmojiInput` やルーティングは変更していない。独立したスマホアプリの試作ではない。

2026-09-20: 大まかな方向性を確認し、Cloudflare全面移行 #28 の完了後に導入するため保存。[保存記録・再開手順](./HANDOFF.md) を起点にする。

## 起動

リポジトリのルートで実行:

```sh
npm run dev:palette
# http://127.0.0.1:4178/
# Jevを有効にする場合（秘密ファイルはリポジトリ外）:
TYPESAFE_API_KEY_FILE=/path/to/private-key-file npm run dev:palette
npm run build:palette
# dist/palette-prototype/
npx tsc --project prototypes/emoji-palette/tsconfig.json
npx eslint prototypes/emoji-palette/*.ts prototypes/emoji-palette/*.tsx
# APIキー不要の回帰テスト:
./node_modules/.bin/esbuild prototypes/emoji-palette/jev-server.test.ts --bundle --platform=node --format=cjs --outfile=/tmp/fanmark-jev-server.test.cjs
node --test /tmp/fanmark-jev-server.test.cjs
```

## 試せること

初期値は操作例として 🌸🌿。3つ目の「＋」から開き、「美容室」で 💈 ✂️ 💇 を続けて選ぶと5個になる。

- 日本語・英語の検索。UI言語と検索言語は独立。カタカナ/ひらがな・全角/半角の差を一部吸収。
- 既存カタログ3,944件を検索。肌色違いはチェックボックスで展開でき、肌色を明示した検索でも対象にする。表示は64件ずつ追加できる。
- 選択後もパレットと検索語を保持。内外の入力欄は同じ状態を使う。
- 既存の絵文字を押すと1個の置き換え。候補を選ぶと閉じる。
- 絵文字左横の小さい「＋」はその前への挿入。後続をずらす。空スロットを飛ばした場合は末尾へ詰める。
- ×で削除、左右矢印で並べ替え、直前操作をUndo。パレット内の「すべてクリア」で入力中の絵文字をまとめて消去でき、Undoで並びと挿入位置・置換モードも復元する。検索語・候補・履歴は保持し、空の場合はクリアを無効にする。5個になったら追加だけを止め、削除・置き換えは可能。
- 最近選んだ絵文字をこのブラウザーのlocalStorageへ最大24件保存。画面には直近8件を表示し、履歴消去も可能。検索語は保存しない。Undo/削除後も「選んだ履歴」は残す試作仕様。
- Clipboard APIで入力文字列をコピー。拒否時は手動コピーを案内。
- Tab/Shift+Tab、Escape、フォーカス復帰に対応。検索欄のEnterは候補へフォーカスし、自動で絵文字を追加しない。IME変換中のEnterでは候補へ移動しない。
- 狭いブラウザー幅では下部シート表示。実機のソフトウェアキーボード表示は別途検証が必要。

## 検索の範囲

Unicode CLDRの日本語名・キーワードと既存カタログの英語名・キーワードを即時検索する。試作用の手作業の連想辞書は撤去した。ローカル検索は既存の名称・キーワードとの文字一致のみで、Jevへの候補の絞り込みには使わない。Jevが有効なら、推論結果を受け取って候補の先頭に追加する。肌色違いの表示切り替えは検索表示用で、既存UUIDや同一性の正規化を変更しない。

データはバンドルに同梱する。初期JSはgzip約310KBで、製品版の遅延ロード・インデックス最適化は別工程。分析ログ・Supabase呼び出しはない。開発時にはViteのHMR通信がある。

## Jev接続

`useJevSearch.ts` → 同一オリジンの `POST /api/palette/jev` → `jev-server.ts` → TypeSafe API。`jev-latest` を指定し、接続確認時の実モデルは `jev-1.13.0`。APIキーはサーバーの `TYPESAFE_API_KEY`、または `TYPESAFE_API_KEY_FILE` のファイル（1行のキー、またはMarkdownコードブロック）から実行時に読む。`VITE_` 変数やブラウザーへ渡さない。キー未設定でも辞書検索は使える。

- 2〜160文字で、IME変換確定後・350ms入力が止まった時に送信。入力変更・閉じる・無効化で待機と通信をキャンセルし、古い結果を表示しない。
- 1段目は既存マスターの大分類を最大125件ずつに分割して選択肢にする。主題・場所・気持ち・関連道具・身体的な反応・比喩と象徴の6観点を、それぞれJevで選ぶ。文房具/日用品等の細分類を独立した絞り込み境界にしない。各観点で確率が正の上位2グループを展開する（場所のイメージと比喩・象徴は上位6グループを2群ずつ別の質問で評価）。「該当なし」が選ばれた観点は展開しない。
- 場所は、既知の地名について街の景色・文化・食べ物・服装・雰囲気を思い浮かべるイメージ提案として評価する。地名に完全一致する絵文字がないだけでは該当なしにせず、部分的で一般に伝わる連想も認める。未知の地名・弱い関連は該当なしにできる。地名別の固定辞書は追加しない。場所候補は確率0.05未満を表示から除く（他の観点は0.01）。これは弱い候補を減らす試作用の表示基準であり、確率を関連性や正解率と解釈しない。
- 比喩と象徴は、具体的な道具とは独立してカテゴリから探す。文章内の技術・方法・抽象的な概念を、一般に伝わる視覚的な連想で表す。弱い連想を無理に足さず、該当なしを許容する。特定の検索語と絵文字の対応はハードコードしない。
- 肌色違いも各IDを保持して分類に含める。1段目の説明だけ、繰り返す肌色表記をまとめて送信量を抑える。2段目には元の名前・ID・肌色を渡す。
- 2段目はJevが選んだグループ内の絵文字から選ぶ。各問は最大250件＋該当なし＝251択で、公式上限255以内。手作業の連想語・ローカル検索の結果・表情全体の特別追加は使用しない。名称・説明・カテゴリは既存マスターとCLDRから取得する。
- 候補を観点ごとに交互に並べて最大12件を表示する。異なる問の確率は大小比較せず、正解率として表示しない。両段階ともトークン上限対策として2問ずつに分けて並列実行する。1段目は3リクエスト、2段目は該当する観点数と場所のイメージ・比喩・象徴の分岐数に応じて最大5リクエスト。最大8 HTTPリクエスト、待ち合わせは2段階。分類説明を全5問へ重複送信する単一リクエストは `max_tokens_exceeded` で失敗したため採用していない。
- Jev候補が不適切・不足の場合にも、辞書候補と「すべて」の一覧から全カタログに到達できる。観点の検出や上位分類から漏れる可能性はあり、全件の意味検索精度を保証しない。
- TypeSafeへ送るユーザーデータは検索語のみ。候補の説明も送るが、選択中の絵文字・履歴・アカウント情報は送らない。この試作では検索語の永続保存・学習ログ収集を行わない。検索語と結果はサーバーメモリー内で10分・最大128件までキャッシュする。TypeSafe側のデータ保持は別途サービス規約に従う。
- サーバーはloopback限定、Origin・専用ヘッダー検証、2KB本文上限、同時2件・毎分30件、全体12秒タイムアウト。失敗時は辞書検索へ戻り、プロバイダーの生エラーをブラウザーへ返さない。

APIはVite開発サーバー限定。`build:palette` の静的成果物にAPIや秘密は含まれず、静的配信だけではJevは動かない。本番化時はCloudflare Worker等へサーバー処理を移し、認証・利用制限・運用監視を別途設計する。

## 出典

- 絵文字ID/英語名: リポジトリ内 `src/data/emojiCatalog.ts`（直接変更しない）
- 日本語名/キーワード: [Unicode CLDR JSON](https://github.com/unicode-org/cldr-json/tree/1aaabe99aa652d6f22ea488cf25baea46aa69b42)、commit `1aaabe99aa652d6f22ea488cf25baea46aa69b42`
- `cldr-json/cldr-annotations-full/annotations/ja/annotations.json` と `cldr-json/cldr-annotations-derived-full/annotationsDerived/ja/annotations.json` を統合した `ja-annotations.json`
- ライセンス: 同梱の `UNICODE-LICENSE.txt`
- Jev: [Choice](https://docs.typesafe.ai/primitives/choice)、[API](https://docs.typesafe.ai/api)

CLDRの名称は既存マスターのemojiへ照合して付加する。CLDR側に追加された絵文字を本番マスターへ追加する処理はない。本番のUnicode更新とは分離した試作スナップショット。

## 確認

ブラウザーで日本語/英語検索、3つ目からの連続追加、5個上限、削除後の再追加、Undo、置き換えによる自動クローズ、途中挿入時の後続保持、重複追加、該当なし、履歴表示を確認。1280px幅と390px幅で表示を確認。コピーAPI成功表示を確認（実アプリへの貼り付けは未確認）。

初回接続時はJev実APIで「美容室」→ 💈 💇 💇‍♀️ ✂️、「美しい夕焼けを見てほっとした」→ 🌇 😌、英語の `quiet encouragement` を確認。キャッシュなしの実測は約0.6〜1.8秒（350msの入力待機を除く）。少数の試行であり、速度保証や多言語の品質評価ではない。候補分割の全件カバレッジ・255制限、入力検証、外部Origin拒否、不正応答・認証失敗時のエラー処理も確認。

旧方式の複数観点への修正時には、「東京の美味しいラーメン」→ 🍜 🗼 😋 🤤 が先頭に並ぶことを実APIとブラウザーで確認（約2.2秒、入力待機を除く）。英語の `delicious ramen in Tokyo` でも同じ4候補が先頭に並ぶことを確認（約2.3秒）。「ラーメン」単独では場所・表情は追加されず、「美容室」の候補も維持された。それ以前の「全体に最も合う候補」では 🍜 のみだった。同じ文の固定辞書登録は行っていない。回帰テストは主題への集中がほかの観点を消さないこと、該当しない観点を追加しないこと、候補数制限・全件到達・カテゴリ制限を検証する。実モデルによる意味解釈は確率的で、常に同じ候補を保証するものではない。

連想辞書撤去・階層検索への変更後、実APIで「東京の床屋」「美容室」「barber shop in Tokyo」に ✂️ が含まれることを確認。「東京の美味しいラーメン」は 🍜・🗼・😋・🤤 を含み、肌色違いを含めた「床屋」も成功した。今回のキャッシュなし応答は約0.7〜1.6秒（350ms待機を除く）。少数の例での検証であり、全言語・全語句の検索精度は未評価。

比喩・象徴の追加後、「AIを使ったコンサル」で 💡・🧠・🤖・💻 が先頭に並ぶことを実APIで確認（約1.7秒）。英語の `AI-powered consulting` でも 🤖 を確認。語句と絵文字の固定対応は追加していない。比喩経路の第6候補カテゴリまでを評価できること、各質問の255択制限、各リクエストの2問上限を回帰テストで確認。

場所のイメージ検索を追加後、実APIで「京都」→ 👘・🍵・🌸・⛩️、「原宿」→ ⛩️・🎀・🛍️・🍦・🧋 等を確認（最終試行で約1.4〜1.5秒）。英語の `Kyoto` / `Harajuku` も候補が出た。架空地名の試験文字列では都市・地図の汎用候補が出る例もあり、未知地名の判別は未解決。地名を特定・検証する機能ではなく、連想の品質は引き続き評価対象。

本番統合、認証、取得処理、LLM蒸留、辞書の更新配信、全言語の検索品質評価はこのサンプルの対象外。
