# fanmark.id — ファンマが暮らす小さな惑星

[ヒーロー刷新 #27](https://github.com/kanouk/fanmark-id/issues/27) のThree.js試作。**実際のトップページを使い、ヒーローと検索エリアの入力UIを差し替える**。新パレット #26 の統合確認も兼ねる。お店、人、ネコ、ウサギが同じ惑星に登場する。通常の本番エントリでは従来のヒーローを表示する。本番には未導入。

## 起動

既存フロント依存がインストール済みの環境で:

```sh
npm ci --prefix prototypes/hero-world
TYPESAFE_API_KEY_FILE=/path/to/private-key-file npm run dev:hero
# http://127.0.0.1:4179/
npx tsc --project prototypes/hero-world/tsconfig.scene.json
npx tsc --project prototypes/hero-world/tsconfig.json
npx eslint prototypes/hero-world/*.ts prototypes/hero-world/*.tsx src/components/RecentFanmarksScroll.tsx
npm run build:hero
# dist/hero-world/
```

Three.jsと型定義は試作配下のロックで0.186.0に固定。通常の本番バンドルにはThree.jsを含めない。全画面の型検査は既存アプリの設定を継承し、描画コードは `tsconfig.scene.json` でstrict検査する。

## 表現と操作

- 花屋とカフェを残し、8人とネコ2匹・ウサギ2匹を含む12キャラクターと8店舗を全球へ配置する。キャラクターは球面全体から次の行き先をランダムに選び、向きを滑らかに変えながら歩く。店舗への接近は回避する。球全体を収めず、街に寄った構図にする。
- 建物は人との比率を見直し、初期版の約1.5倍に拡大。曲がる道、店先の広場、木立と低木、木製ベンチ、街灯、花鉢、木の道しるべを配置する。見える操作注釈は置かず、アイコンボタンと読み上げ用ラベルを残す。
- ファンマの吹き出しは実際の頭の位置から画面上方向へ離して配置し、カメラへ向ける。本人の頭を覆わず、歩行中も追従する。
- ドラッグ・矢印キー・左右ボタンで回転。＋／−で拡大縮小、Ctrl/Cmd＋ホイールにも対応。タッチの縦方向はページスクロールを優先する。ピンチはブラウザーのページ拡大に任せる。
- 停止／再生、視点・ズーム・歩行位置のリセット。ファンマを押すとコピー。キーボード用の同等ボタンはフォーカス時に表示する。
- 「サンプル」「この星の住人」、SMALL PLANET等のサブタイトルや、小さな世界の一員になるという文言は置かない。見出し・CTA・ヘッダー・使い方・フッターは既存トップを使用する。検索エリアの動作は既存処理を再利用する。
- 静止画は作らない。読み込み失敗時は短い案内と再試行を表示し、HTMLの開始ボタンと既存検索は使用可能。

## 公開ファンマの固定割り当て

`useRecentFanmarks` が既存の公開RPC `list_recent_fanmarks(p_limit: 20)` を取得し、Index → PlanetHeroへ渡す。元のスクロール表示は試作ヒーローから削除した。通常の本番エントリでは同じフックを使った従来スクロールが残る。DB変更はない。

12キャラクターの吹き出しと8店舗の看板へ、初回ロード時に公開ファンマを優先して一度だけ割り当てる。不足分は試作用の絵文字を補う。以降は経過時間・視点変更・リセット・公開一覧の再取得でファンマを変更しない。取得中は未表示、0件・失敗時は試作用の絵文字を割り当てる。長い絵文字列も看板内へ収める。

キャラクターと店は装飾用モデルであり、所有者の姿・業種を推定したものではない。公開絵文字だけを取得し、人物のプロフィール情報は取得しない。補完したファンマの取得可能性は保証しない。クリックはコピーのみで、取得・決済や外部サイトへの自動移動は行わない。

**プレビューも既存Supabase設定につながった実アプリ**。検索や認証等の既存画面は実際の動作を持つ。孤立したモックではないため、検証時に登録・決済等を不要に実行しない。今回の確認ではこれらの書き込みを行っていない。

## 構造と移植

- `main.tsx`: 実アプリのThemeProviderと `App homeHero={PlanetHero} homeInput={PaletteInput}` を起動。
- `src/App.tsx` / `src/pages/Index.tsx`: 任意のヒーロー・入力UI差し替え口。未指定なら従来表示。
- `src/hooks/useRecentFanmarks.ts`: 公開データ取得を共有。従来の `RecentFanmarksScroll` も同じフックを使う。
- `PlanetHero.tsx`: 既存翻訳の見出し・CTA、3Dの遅延import、操作、コピー、失敗時の再試行。
- `world.ts`: 手続き的なモデル、歩行・吹き出し、回転・ズーム・選択、描画とリソース解放。
- `places.ts`: 装飾キャラクターの色、全球に分散した初期位置、補完するファンマ。
- `styles.css`: `.planet-*` 内にスコープした専用スタイル。
- `vite.config.ts`: ポート4179、既存publicとsrcを参照する独立エントリ。

Cloudflare移行 #28 では最近取得APIの既存データ契約を維持し、公開絵文字の配列を渡せばよい。Three.js側にはSupabaseへの依存を持たせない。新パレット #26 の単独版は別ブランチに保存済み。本試作では入力部分を `PaletteInput.tsx` として接続し、検索・Jevロジックを単独版と共有する。本番統合は #28 完了後とする。

## 負荷と検証

上限30fps、DPR上限PC1.5／狭い画面1.25、画面外・非表示タブ・停止中は継続描画を止める。OSの動き低減設定で初期停止し、変更にも追従する。静止物を材質ごとにまとめ、影は軽い接地影テクスチャを使用する。物理演算・外部3Dモデル・リアルタイム影・ポストプロセスは使用しない。終了時はRAF、observer、イベント、geometry/material/texture、rendererを破棄する。

今回の版でデスクトップ表示、公開ファンマの描画、吹き出し直接クリックによるコピーとクリップボード内容、ドラッグ回転とドラッグ後の誤選択防止、＋／−のズーム値変更を確認。型検査・対象Lint・試作と通常アプリのビルドは成功。補完ファンマのキーボードコピーと、不要文言・スクロール表示の撤去も確認した。

モバイル用レイアウトは実装済みだが、今回のブラウザー環境ではviewport指定が反映されず、最新版の390px表示は未確認。前版のモバイル確認をこの版の合格として流用しない。実機のタッチ・発熱・消費電力・FPS、LCP/CLS、低速回線、WebGL故障注入、スクリーンリーダーは本番採用前に検証する。追加操作文言は日本語と英語を用意し、韓国語・インドネシア語では英語にフォールバックするため、本番統合時に翻訳辞書へ移す。

保存ブランチ: `codex/hero-emoji-world`。本番採用・性能評価は #27 で継続する。

## 検索エリアとパレットの統合（2026-09-20）

`PaletteInput.tsx` は `EmojiInputProps` のcontrolled value/onChangeに合わせた入力UI。`palette.css` は `.fanmark-palette` 内にスコープし、既存画面に広がらない。`FanmarkAcquisition` → `FanmarkSearch` の任意inputComponentで接続し、空き状況・取得・お気に入り・抽選・アクセス・認証への引き継ぎは既存コンポーネントが担当する。通常エントリと管理画面の入力は従来のまま。

- 最大5個、連続追加、置き換え、途中挿入、削除、矢印/ドラッグ並べ替え、Undo、履歴、カテゴリ/肌色選択、Jevの提案を維持。
- 既存の直接入力・貼り付け・クリア・正規化・検索内容の復元に同期する。外側から入力が変わった際は古いUndoを破棄する。カタログ未収録の入力も表示から消さず保持する。
- 共有 `useFanmarkSearch` に検索世代の照合を追加し、連続選択中の古い応答が最新の空き状況を上書きしないようにする。入力変更/クリア時は旧結果を直ちに消す。同じ値の再入力では取得状態を消さない。
- `jevPlugin(4179)` でローカルAPIを提供。単独版は既定の4178を使用し、Host/Originのポート制限を維持する。キーはサーバー側のみ。キーなしでも名称検索は可能。静的ビルドにJevサーバーは含まれず、Cloudflare Worker化は #26/#28 の後続作業。

確認済み: Jev実APIから美容室の候補を表示し、💈・✂️を連続追加。5個制限、置き換え、途中挿入、個別削除、矢印並べ替え、パレット内クリア→Undo、外側の直接入力・コピー・貼り付け・クリア、同じ値の貼り付け後も取得導線が有効なこと、認証画面への移動と戻った際の入力復元をブラウザーで確認した。入力直後にクリアした後も取得ボタンが無効のままであることを確認。型検査・対象Lint・通常アプリ/単独パレット/統合試作のビルドと既存Jev回帰テスト8件が成功。

取得・お気に入り・抽選・課金は既存コードを再利用しているが、実データへの登録/決済/抽選参加を伴う操作のE2E確認は行っていない。強制的に応答順を逆転させる試験、実機タッチでのドラッグとIME、全言語・アクセシビリティは本番採用前の確認項目。追加パレット文言は日本語/英語で、他言語は英語にフォールバックする。DB変更・本番デプロイなし。
